# ระบบรับคำขอจากเว็บ (Google Sheets + Apps Script) — ตั้งค่าเองได้ใน ~10 นาที

เมื่อตั้งค่าตามคู่มือนี้ ทุกคำขอจากเว็บ (ฟอร์มติดต่อ · ขอใบเสนอราคา · จองคิวล้างแอร์) จะ

- **เข้าเป็น 1 แถวใน Google Sheet** ของบริษัท (แท็บชื่อ `คำขอ`) พร้อมเวลาไทย เลขอ้างอิง ชื่อ เบอร์โทร ฯลฯ
- **ส่งอีเมลแจ้งทีม** (ข้อความธรรมดา พร้อมลิงก์เปิดชีต) — กด "ตอบกลับ" ในอีเมลก็ตอบลูกค้าได้เลยถ้าลูกค้าให้อีเมลไว้
- หน้าเว็บขึ้นว่า **"ส่งถึงทีมแล้ว"** เฉพาะเมื่อบันทึกลงชีตสำเร็จจริงเท่านั้น ถ้าไม่สำเร็จ เว็บจะบอกตรง ๆ แล้วให้ลูกค้าส่งทาง LINE / โทร แทน

ใช้ของฟรีทั้งหมด (บัญชี Google ของบริษัท + GitHub ที่ใช้อยู่แล้ว) ไม่ต้องสมัครบริการอื่น
โค้ดฝั่ง Google อยู่ไฟล์เดียว: [`backend/google-apps-script/Code.gs`](google-apps-script/Code.gs)

> แนะนำให้ทำด้วย **บัญชี Google ของบริษัท** (ไม่ใช่บัญชีส่วนตัวของพนักงาน) เพราะชีตและอีเมลแจ้งเตือนจะผูกกับบัญชีที่ทำขั้นตอนนี้

## ขั้นตอนตั้งค่า

### ส่วนที่ 1 — ฝั่ง Google (ประมาณ 6 นาที)

1. **สร้าง Google Sheet ใหม่** ที่ <https://sheets.new> แล้วตั้งชื่อไฟล์ เช่น `SBP AirCare · คำขอจากเว็บ`
   (ไม่ต้องสร้างแท็บหรือหัวตารางเอง ระบบสร้างแท็บ `คำขอ` พร้อมหัวตารางให้ตอนมีคำขอแรก)

2. ในชีตนั้น ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script** จะเปิดหน้าต่างเขียนโค้ดขึ้นมา

3. **วางโค้ด**
   - เปิดไฟล์ [`Code.gs` บน GitHub](https://github.com/babayeka11-web/Project-test-web/blob/main/backend/google-apps-script/Code.gs)
     แล้วกดปุ่ม **Copy raw file** (ไอคอนสี่เหลี่ยมซ้อนกัน มุมขวาบนของโค้ด)
   - กลับมาที่ Apps Script ลบโค้ดเดิมในไฟล์ `Code.gs` ทั้งหมด (`function myFunction() {}`) แล้ววางโค้ดที่คัดลอกมา
   - กด **บันทึก** (ไอคอนแผ่นดิสก์ หรือ Ctrl+S / ⌘+S) และตั้งชื่อโปรเจกต์มุมซ้ายบน เช่น `SBP คำขอจากเว็บ`

4. **ตั้งอีเมลที่จะรับแจ้งเตือน**
   - แถบซ้าย กดไอคอนเฟือง **การตั้งค่าโปรเจกต์ (Project Settings)**
   - เลื่อนลงไปที่ **พร็อพเพอร์ตี้ของสคริปต์ (Script Properties)** → **เพิ่มพร็อพเพอร์ตี้ของสคริปต์ (Add script property)**
   - Property: `NOTIFY_EMAIL` · Value: อีเมลทีม เช่น `service@บริษัท.com`
     (หลายอีเมลให้คั่นด้วยจุลภาค เช่น `a@x.com,b@x.com` · ไม่ใส่เลย = บันทึกลงชีตอย่างเดียว ไม่ส่งอีเมล)
   - กด **บันทึกพร็อพเพอร์ตี้ของสคริปต์ (Save script properties)**

5. **เผยแพร่เป็นเว็บแอป**
   - ปุ่มสีน้ำเงินขวาบน **การทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ (New deployment)**
   - กดไอคอนเฟืองข้าง "เลือกประเภท (Select type)" → เลือก **เว็บแอป (Web app)**
   - คำอธิบาย (Description): `เว็บไซต์ v1`
   - **ดำเนินการในฐานะ (Execute as): ฉัน (Me)**
   - **ผู้ที่มีสิทธิ์เข้าถึง (Who has access): ทุกคน (Anyone)** ← ต้องเป็น "ทุกคน" ไม่ใช่ "ทุกคนที่มีบัญชี Google" ไม่อย่างนั้นลูกค้าส่งไม่ได้
   - กด **ทำให้ใช้งานได้ (Deploy)**

   > **สองช่องนี้หมายความว่าอะไร**
   > - **Execute as: Me** — ทุกคำขอจากอินเทอร์เน็ตทำงานด้วยสิทธิ์ของ **บัญชีที่ทำขั้นตอนนี้** (ไม่ใช่ของลูกค้า): เขียนลงชีตนี้
   >   และส่งอีเมลแจ้งเตือนจากบัญชีนี้ (อยู่ในกล่อง "ส่งแล้ว" ของบัญชีนี้ และนับโควตาอีเมลของบัญชีนี้) ลูกค้าไม่ต้องล็อกอิน และมองไม่เห็นชีต
   > - **Who has access: Anyone** — ใครก็ส่งคำขอเข้า URL นี้ได้โดยไม่ต้องล็อกอิน (จำเป็น เพราะลูกค้าไม่ได้ล็อกอิน Google)
   >   URL จะอยู่ในโค้ดหน้าเว็บ จึงถือว่าคนนอกรู้ได้ สคริปต์ตรวจทุกคำขอและจำกัดจำนวนต่อนาที แต่กันคนที่ตั้งใจยิงคำขอปลอมได้ไม่ 100%
   >   (ดู [ขีดจำกัด](#ขีดจำกัดของบริการฟรี)) — ส่วนการ **อ่าน** ข้อมูลในชีตผ่าน URL นี้ทำไม่ได้
   > - สคริปต์ขอสิทธิ์เฉพาะ **ไฟล์ชีตนี้ไฟล์เดียว** (บรรทัด `/** @OnlyCurrentDoc */` ในโค้ด — ห้ามลบ) กับการส่งอีเมล ไม่แตะไฟล์อื่นใน Drive

6. **อนุญาตสิทธิ์ (ครั้งแรกครั้งเดียว)**
   - กด **ให้สิทธิ์เข้าถึง (Authorize access)** → เลือกบัญชี Google ของบริษัท
   - ถ้าขึ้นหน้า "Google ยังไม่ได้ยืนยันแอปนี้ (Google hasn't verified this app)" เป็นเรื่องปกติของสคริปต์ที่เราเขียนเอง
     ให้กด **ขั้นสูง (Advanced) → ไปที่ SBP คำขอจากเว็บ (ไม่ปลอดภัย)** แล้วกด **อนุญาต (Allow)**
   - ถ้ามีช่องให้ติ๊กเลือกสิทธิ์ ให้ติ๊ก **เลือกทั้งหมด (Select all)** แล้วกด **ดำเนินการต่อ (Continue)** — ขาดข้อใดข้อหนึ่ง สคริปต์จะทำงานไม่ได้
   - สิทธิ์ที่ขอต้องมีแค่ 2 ข้อ: จัดการ **สเปรดชีตที่ติดตั้งสคริปต์นี้** (_View and manage spreadsheets that this application has been installed in_)
     และ **ส่งอีเมลในนามของคุณ** (_Send email as you_)
   - ถ้าเห็นสิทธิ์เข้าถึง **สเปรดชีตทั้งหมด** (_See, edit, create, and delete all your Google Sheets spreadsheets_) แปลว่าโค้ดที่วางไม่ครบ
     (ขาดบรรทัด `/** @OnlyCurrentDoc */`) → กดยกเลิก แล้วทำข้อ 3 ใหม่

7. **คัดลอก URL ของเว็บแอป** (Web app URL) ที่ขึ้นมา หน้าตาแบบ
   `https://script.google.com/macros/s/AKfy…ยาว ๆ…/exec` — ต้องลงท้ายด้วย **`/exec`**
   (บัญชี Google Workspace อาจได้ `https://script.google.com/a/macros/ชื่อโดเมน/s/…/exec` ก็ใช้ได้เหมือนกัน)
   ใช้ URL ตามที่คัดลอกมาตรง ๆ — อย่าย่อด้วยบริการย่อลิงก์ และอย่าเปลี่ยนเป็น `http://`

8. **ทดสอบในเบราว์เซอร์** เปิด URL นั้นในแท็บใหม่ ต้องเห็นข้อความแบบนี้
   ```json
   {"ok":true,"service":"sbp-requests","version":"1.0.0"}
   ```
   ถ้าเห็นหน้าให้ล็อกอิน Google แทน แปลว่าข้อ 5 ไม่ได้เลือก "ทุกคน (Anyone)" — ดู [แก้ปัญหา](#แก้ปัญหา)

### ส่วนที่ 2 — ฝั่ง GitHub (ประมาณ 4 นาที)

9. **ใส่ URL ให้เว็บ** ที่ <https://github.com/babayeka11-web/Project-test-web>
   - **Settings → Secrets and variables → Actions** → แท็บ **Variables** → ปุ่ม **New repository variable**
   - Name: `FORM_ENDPOINT` · Value: URL `/exec` จากข้อ 7 → **Add variable**
   - (ใช้ "Variables" ไม่ใช่ "Secrets" เพราะ URL นี้จะอยู่ในหน้าเว็บอยู่แล้ว ไม่ใช่ความลับ — URL นี้รับคำขอได้อย่างเดียว อ่านข้อมูลในชีตไม่ได้)

10. **สร้างเว็บใหม่ให้ใช้ URL นี้**
    - แท็บ **Actions** → เลือก **Deploy to GitHub Pages** ทางซ้าย → ปุ่ม **Run workflow** → Branch: `main` → **Run workflow**
      (หรือ push / merge งานใหม่เข้า `main` ก็ได้ผลเหมือนกัน)
    - รอจนขึ้นเครื่องหมายถูกสีเขียว ประมาณ 3–5 นาที

11. **ลองส่งคำขอจริง 1 ครั้ง**
    - เปิด <https://babayeka11-web.github.io/Project-test-web/contact/> (กด Ctrl+Shift+R / ⌘+Shift+R เพื่อโหลดหน้าใหม่)
    - ปุ่มด้านล่างฟอร์มต้องเปลี่ยนเป็น **"ส่งข้อความถึงทีม"** (ถ้ายังเป็น "สร้างสรุปข้อความ" แปลว่าเว็บยังไม่ได้ URL — ดูข้อ 9–10)
    - กรอกชื่อว่า `ทดสอบระบบ` แล้วกดส่ง → ต้องขึ้น **"ส่งถึงทีมแล้ว"** พร้อมเลขอ้างอิง
    - เปิด Google Sheet → แท็บ **`คำขอ`** มีแถวใหม่ และอีเมลแจ้งเตือนเข้ากล่อง `NOTIFY_EMAIL` (ถ้าไม่เห็น ลองดูในสแปม)
    - เสร็จแล้วลบแถวทดสอบทิ้งได้

เสร็จแล้ว จากนี้ทุกคำขอจากเว็บจะเข้าชีตนี้

| B เลขอ้างอิง | `SBP-ปปดดวว-XXXX` (ปี พ.ศ.) เลขเดียวกับที่ลูกค้าเห็นและแจ้งทาง LINE / โทร |

| K สถานะ | ระบบใส่ `ใหม่` ให้ ทีมเปลี่ยนเองได้ เช่น ติดต่อแล้ว · นัดแล้ว · เสร็จ · ยกเลิก |
| L รายละเอียดทั้งหมด | สรุปคำขอเต็ม ๆ (รายการ ราคา หมายเหตุ ฯลฯ) |

ข้อควรระวัง

- **อย่าเปลี่ยนชื่อแท็บ `คำขอ`** (ถ้าเปลี่ยน ระบบจะสร้างแท็บ `คำขอ` ใหม่ให้)
- **อย่าแทรกหรือลบคอลัมน์ A–L** — อยากเพิ่มคอลัมน์ของทีม (เช่น ช่างที่รับงาน) ให้เพิ่มต่อทางขวาตั้งแต่คอลัมน์ M
- ทำเมนูเลือกสถานะได้: เลือกคอลัมน์ K → **ข้อมูล → การตรวจสอบข้อมูล** → เพิ่มกฎ "เมนูแบบเลื่อนลง"
- ลูกค้ากดส่งซ้ำ (เน็ตหลุดแล้วลองใหม่) ด้วยเลขอ้างอิงเดิมภายใน 10 นาที ระบบเก็บไว้แถวเดียว ไม่ซ้ำ
- **จะดาวน์โหลดไปเปิดใน Excel ให้เลือก .xlsx** (ไฟล์ → ดาวน์โหลด → Microsoft Excel) **อย่าใช้ .csv** —
  ในชีตเองทุกช่องบันทึกเป็นข้อความเสมอ แต่ไฟล์ .csv ไม่เก็บข้อนี้ไว้ ข้อความที่ใครพิมพ์ขึ้นต้นด้วย `=` จะกลายเป็นสูตรใน Excel ได้

## อัปเดตสคริปต์

เมื่อมี `Code.gs` เวอร์ชันใหม่

1. เปิดชีต → **ส่วนขยาย → Apps Script** → ลบโค้ดเดิม วางโค้ดใหม่ทั้งไฟล์ → **บันทึก**
2. **Deploy → จัดการการทำให้ใช้งานได้ (Manage deployments)** → เลือกรายการเดิม → กดไอคอนรูปดินสอ (แก้ไข)
3. ช่อง **เวอร์ชัน (Version)** เลือก **เวอร์ชันใหม่ (New version)** → **Deploy**
4. **URL เดิมใช้ต่อได้** ไม่ต้องแก้อะไรใน GitHub — เปิด URL ในเบราว์เซอร์เพื่อดูว่า `version` เปลี่ยนแล้ว

> **ข้อควรระวัง:** อย่ากด "New deployment" ตอนอัปเดต เพราะจะได้ URL ใหม่ ต้องไปแก้ `FORM_ENDPOINT` ใน GitHub และสร้างเว็บใหม่อีกรอบ

## ขีดจำกัดของบริการฟรี

- **อีเมลแจ้งเตือน:** บัญชี Gmail ฟรีส่งได้ประมาณ **100 ผู้รับต่อวัน** (Google Workspace ประมาณ 1,500) — นับต่อผู้รับ
  ใส่ 2 อีเมลใน `NOTIFY_EMAIL` = ใช้ 2 ต่อคำขอ ถ้าเกินโควตา คำขอ **ยังบันทึกลงชีตครบ** แค่ไม่มีอีเมลแจ้ง — ดูในชีตได้เสมอ
- **กันสแปม:** ระบบบันทึกไม่เกิน **20 คำขอต่อนาที** ทั้งเว็บ (คำขอที่ระบบไม่รับไม่นับ เกินแล้วเว็บบอกลูกค้าให้ลองใหม่ในอีก 1 นาที
  หรือส่งทาง LINE / โทร) ปรับได้ที่บรรทัด `RATE_LIMIT_PER_MINUTE` ใน `Code.gs`
- **ถ้ามีคนตั้งใจยิงคำขอปลอม** (เห็นแถวขยะในชีตจำนวนมาก): ระบบไม่มีทางรู้ว่าใครส่ง จึงกันได้แค่จำนวนต่อนาที —
  ทำ **New deployment** ใหม่ (ได้ URL ใหม่) → เก็บถาวร (Archive) อันเดิม → เปลี่ยน `FORM_ENDPOINT` ใน GitHub แล้ว Run workflow (ข้อ 9–10)
  หรือปิดระบบชั่วคราวตาม [ปิดระบบ](#ปิดระบบ-กลับไปใช้แบบส่งต่อเอง)
- **ขนาดคำขอ:** สรุปไม่เกิน 8,000 ตัวอักษร ทั้งคำขอไม่เกิน 20,000 ตัวอักษร (คำขอปกติใช้ไม่ถึง 3,000)
- ช่องที่ซ่อนไว้ในฟอร์ม (honeypot) ถ้ามีการกรอกมา = บอต ระบบไม่บันทึก

## ความเป็นส่วนตัว (PDPA)

ชีตนี้เก็บ **ข้อมูลส่วนบุคคลของลูกค้า** (ชื่อ เบอร์โทร อีเมล ที่อยู่) และเว็บแจ้งลูกค้าไว้ว่า
"ข้อมูลที่กรอกใช้เพื่อติดต่อกลับเรื่องคำขอนี้เท่านั้น" จึงควร

- **แชร์ชีตเฉพาะพนักงานที่ต้องใช้** (แชร์รายคนด้วยอีเมล) — **ห้ามเปิด "ทุกคนที่มีลิงก์"**
- คนที่เป็น **ผู้แก้ไข (Editor)** ของชีต เปิด Apps Script และแก้โค้ดได้ด้วย (โค้ดทำงานในนามบัญชีบริษัท) — ให้สิทธิ์ผู้แก้ไขเฉพาะคนที่ไว้ใจ
  คนที่แค่ดูรายการให้ **ผู้มีสิทธิ์อ่าน (Viewer)**
- เอาสิทธิ์ออกทันทีเมื่อพนักงานลาออก และเปิดการยืนยันตัวตน 2 ขั้นตอนในบัญชี Google ของบริษัท
- ไม่นำข้อมูลไปใช้เรื่องอื่น (เช่น ส่งโปรโมชัน) ถ้าลูกค้าไม่ได้ยินยอม
- ตั้งรอบลบ/เก็บถาวรข้อมูลเก่า เช่น ทุก 1–2 ปี ลบแถวที่งานจบนานแล้ว
- ถ้าลูกค้าขอให้ลบข้อมูล ค้นหาด้วยเลขอ้างอิงหรือเบอร์โทร แล้วลบแถวนั้น (และอีเมลแจ้งเตือนที่เกี่ยวข้อง)

URL `/exec` อยู่ในโค้ดหน้าเว็บซึ่งใครก็เห็นได้ — เป็นเรื่องปกติ เพราะ URL นี้ **รับคำขอเข้าได้อย่างเดียว อ่านหรือแก้ข้อมูลในชีตไม่ได้**

---

## ปิดระบบ (กลับไปใช้แบบส่งต่อเอง)

1. GitHub → **Settings → Secrets and variables → Actions → Variables** → ลบ `FORM_ENDPOINT`
2. **Actions → Deploy to GitHub Pages → Run workflow** (branch `main`)
3. เว็บกลับไปเป็นแบบเดิม: สร้างสรุปพร้อมเลขอ้างอิง แล้วให้ลูกค้าส่งทาง LINE / โทร / คัดลอก / อีเมล
4. (ถ้าต้องการหยุด URL ด้วย) Apps Script → **Deploy → Manage deployments → เก็บถาวร (Archive)**

ข้อมูลเดิมในชีตยังอยู่ครบ เปิดใช้อีกครั้งได้โดยใส่ `FORM_ENDPOINT` กลับไป (URL เดิมถ้ายังไม่ได้ Archive)

## สำหรับนักพัฒนา

- เว็บส่ง `POST` เป็น JSON ด้วย `Content-Type: text/plain;charset=utf-8` (CORS simple request ไม่มี preflight):
  `{ kind, ref, fields: { ป้ายชื่อ: ค่า }, text, _subject }` — ดู `submitRequest()` ใน [`src/lib/request.ts`](../src/lib/request.ts)
- สคริปต์ตอบ JSON เสมอ (`{ok:true, ref}` หรือ `{ok:false, error}`) เพราะ Apps Script ตั้ง HTTP status ไม่ได้
  เว็บถือว่า "ส่งแล้ว" เมื่อได้ 2xx และ body ไม่ใช่ `{ok:false}` — ถ้า URL (หรือ URL ปลายทางหลัง redirect) เป็นของ Apps Script
  ต้องได้ `{ok:true, ref}` ที่ `ref` ตรงกับคำขอนี้เท่านั้น (`doGet` ตอบ `{ok:true}` ไม่มี `ref` — ถ้ามี redirect ก่อนถึง Google
  เช่น `http://` หรือลิงก์ย่อ POST จะกลายเป็น GET ไปเจอ `doGet` แทน จึงต้องไม่นับเป็นส่งสำเร็จ)
- หัวข้ออีเมลสร้างในสคริปต์จาก `kind` + `ref` เสมอ (`_subject` ที่ส่งมาไม่ถูกใช้) คนส่งจึงตั้งหัวข้ออีเมลถึงทีมเองไม่ได้
- ป้ายชื่อช่องที่จับคู่เป็นคอลัมน์อยู่ใน `FIELD_LABELS` ใน `Code.gs` (ตรงกับ `ContactForm.tsx` และ `RequestSection.tsx`)
  ถ้าเปลี่ยนป้ายชื่อในฟอร์ม ให้แก้ตรงนี้ด้วย ช่องอื่น ๆ จะเข้าคอลัมน์ "รายละเอียดทั้งหมด" อัตโนมัติ
- ทดสอบ: `npx vitest run src/lib/apps-script.test.ts` รัน `Code.gs` ตัวจริงใน `node:vm` กับบริการ Google จำลอง
